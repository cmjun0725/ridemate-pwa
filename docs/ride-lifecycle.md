# 라이딩 일정 및 자동 정리

- 출발 예정 시각에 참여자의 `notifications.ride` 설정과 등록된 FCM 토큰으로 알림을 발송합니다. 브라우저 알림 허용이 필요합니다.
- 매분 스케줄러가 검사하므로 통상 1분 이내 처리되지만 서비스 지연 및 기기 상태에 따라 늦어질 수 있습니다. FCM 일시 실패는 재시도하며 중복 실행은 10분 임대로 제한합니다. 전송 직후 장애에서는 중복 전달 가능성이 있습니다.
- 미출발: 예정 시각 + 24시간. 일정 없는 계획은 만료하지 않습니다.
- 출발: 실제 시작 + 올림(거리km / 평속kmh × 60)분 + 24시간. 휴식 시간은 포함하지 않습니다. 거리·평속 데이터가 유효하지 않은 기존 방은 시간 기반 삭제를 건너뜁니다.
- 참여자 문서가 0개인 방은 정리합니다. 방장도 참여자로 셉니다.
- 정리는 상태 `삭제됨`, `lifecycleDeletedAt`, 비공개 처리이며 물리적 삭제가 아닙니다. 회원 목록과 공개 탐색에서 제외하고 신고·투표 증거는 보존합니다.
- 함께 라이딩은 방장 계정당 미삭제 방 4개(완료·숨김 포함). 개인 계획과 다른 사람 방 참여는 이 제한에 포함하지 않습니다. 생성 트랜잭션으로 동시 요청도 검사합니다.
- 기존 방에도 정책이 적용됩니다. Cloud Scheduler 및 Firestore 사용 비용이 발생할 수 있습니다. 현재 구현은 미삭제 상태의 방을 100개씩 순회하므로 규모 증가 시 만료/알림 시각 인덱스 기반 작업 큐로 전환해야 합니다.

검증: `npm test`, `npm run build`, `npm --prefix functions run build`, `npm run lint`.
서버 함수: `maintainRideLifecycle`, `createRidePlan`, `listMyRidePlans`, `startRide`, `castNoShowVote`.
